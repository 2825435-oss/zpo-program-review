# Технічний звіт про програму

## Зміст і порядок

1. Почни з назви програми та короткої звірки годин. Для кількох років або рівнів використай компактну таблицю. Відрізняй заявлені години, перераховані підсумки та результат порівняння з навчальним планом. Якщо розбіжність потребує уточнення, не подавай очікуваний результат після правки як факт.
2. Спочатку наведи підтверджені розбіжності, які впливають на години, нумерацію або зміст заняття. Потім подай редакційні зауваження. Питання, які неможливо перевірити, та потрібні для цього дані наведи наприкінці. Якщо підтверджених невідповідностей немає, повідом про це.
3. Для кожного зауваження використовуй окремий блок **Критерій / Місце / Пункт / Пропозиція** з основної інструкції. Збирай пов’язані виправлення в один блок, зокрема зміни теми та її підсумків. Не дублюй зауваження у звіті. Давай готовий текст заміни, коли його підтверджує документ. Якщо відомі лише суперечливі варіанти, покажи обидва та вкажи, що треба підтвердити.
4. Показуй увесь чекліст лише на запит. Узагальнений аналіз для практичного завдання не входить до технічної перевірки.

## Файл і відповідь у чаті

- За замовчуванням у цьому самому запуску створи повний звіт **Word (.docx)** засобом створення файлів, доступним у чаті. Якщо користувач попросив PDF, створи **PDF** замість Word або обидва формати, якщо прямо просить обидва. За запитом «лише в чаті» виведи повний звіт у чаті.
- Використай один підготовлений звіт для всіх форматів. У файлі розміщуй блоки зауважень на всю ширину тексту. Таблицю використовуй для стислої звірки годин, а не для довгих цитат і правок. Додай назву програми в заголовок та до імені файла. Для кількох програм чітко розділи їхні звіти.
- Після створення переконайся, що файл існує й доступний для завантаження. У чаті дай короткий підсумок годин, до трьох найважливіших знахідок і посилання на файл. Цифри, сторінки й пропозиції мають збігатися з файлом.
- Якщо засобу створення файла немає або файл не вдалося створити, виведи повний звіт у чаті в тому самому форматі та повідом, що файл не створено. Не показуй посилання на відсутній файл.
- Якщо користувач просить Word чи PDF після готового звіту в цьому чаті, використай наявний звіт. Повторюй перевірку тільки за запитом або якщо змінився вихідний документ.
